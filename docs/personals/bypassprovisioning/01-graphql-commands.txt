==============================================================================
 GraphQL commands for the simulate provisioning -> billing flow
 Run these in the coreui GraphQL playground or Postman (with your auth token).
 Replace OR-XXXXX / ACC / dates with real values.
==============================================================================

------------------------------------------------------------------------------
 #1  STEP 1 - process the order through the engine (in-process, no broker)
------------------------------------------------------------------------------
 - Drives engine PGOrderService.updateStatus directly.
 - Creates subscription + service_unit + price_unit and moves the order to
   PROVISIONING_INITIATED. (Tries NOKIA, no answer -> stays there. Fine.)
 - executeFutureOrderNow: true  is needed ONLY if the order is future-dated;
   it makes the engine process the order as of its effective date.

mutation ProcessOrder {
  updateOrderStatus(input: {
    id: "OR-XXXXX",
    status: SUBMITTED,
    executeFutureOrderNow: true
  }) {
    id
    status
  }
}

------------------------------------------------------------------------------
 #2  STEP 4a - set the engine clock so the billing cycle is due
------------------------------------------------------------------------------
 - Set ccpTime to a date on/after the account's billing_profile.nextbilldate.
 - Date format: 'YYYY-MM-DD'.
 - (Requires useCcpTime = true in CCP Properties.)

mutation SetClock {
  setCcpTime(input: { ccpTime: "2024-07-18" }) {
    ccpTime
  }
}

------------------------------------------------------------------------------
 #3  STEP 4b - run billing for the account (alternative to the UI job)
------------------------------------------------------------------------------
 - Bills the cycle the account's billing_profile currently points to.
 - accountId is the only required field.

mutation RunBilling {
  runBilling(input: { accountId: "ACC" }) {
    id
    status
  }
}

==============================================================================
 NOTES
  - Select-field sets above are minimal; add fields per your schema if needed.
  - Order of use: #1  ->  (verify with SQL + run 02-set-account-provisioned.sql)
                      ->  #2  ->  #3 (or run the billing job in the UI).
  - If runBilling / billing job errors with PENDING_DEFERRED_PURCHASE_JOB, run
    the deferred-purchase job first, then bill again.
==============================================================================
